# Project Governance — Cambodia Trusted AI Document Platform

> **Status:** Active — updated as the project and community evolve.
> **Model:** Maintainer-led open-source project.

---

## 1. Maintainer Model

The **Cambodia Trusted AI Document Platform** is an open-source project created and maintained by **Dy Rongrath** as the sole project owner and lead maintainer during the pre-release and early development stages.

The project uses a **maintainer-led governance model**:

- The project owner makes final decisions on product vision, architecture, security policy, and roadmap priorities.
- Major technical and architectural decisions are recorded transparently using Architecture Decision Records ([docs/adr/](docs/adr/)).
- All changes are submitted via Pull Requests and require maintainer review and approval before merging.
- Security-sensitive changes require explicit human review — AI agents and automated tools cannot self-approve or merge changes (`AGENTS.md` Section 6).

---

## 2. Contributor Pathways

We welcome community contributions from developers, security researchers, AI specialists, and documentation contributors!

### How decisions are made during solo/early development:
- **Small improvements and bug fixes:** Reviewed and merged directly by the maintainer via GitHub Pull Requests.
- **Architectural or security changes:** Require prior discussion in GitHub Issues or an ADR proposal before implementation.
- **Growing the maintainer team:** As contribution volume increases, sustained contributors who demonstrate high-quality code, security awareness, and reliable collaboration may be invited to join as topic reviewers or co-maintainers.

Maintainer status is granted based on merit, code quality, commitment to security and privacy rules, and positive community participation.

## 3. Commercial Use and Neutrality

- **Licence:** The project is licensed under the [Apache License 2.0](LICENSE), which explicitly permits commercial use, modification, distribution, and private deployment.
- **Governance Independence:** Commercial users, sponsors, or enterprise deployers receive no special governance privileges, voting rights, or technical authority solely because they deploy or fund the software. Technical decisions are based strictly on platform quality, privacy, security, and project goals.

## 4. Trademark and Project-Name Policy

- The [Apache License 2.0](LICENSE) grants rights to the software source code, but does **not** grant permission to use the project's trade names, logos, or trademarks.
- You may refer to the platform by name ("Cambodia Trusted AI Document Platform") to accurately describe your use of the open-source code.
- You must not use the project name or logo in a manner that implies official endorsement, sponsorship, or affiliation with the project owner without prior written permission.

---

## 5. Funding and Sponsorship Position

- **Current Status:** The project currently operates without a formal sponsorship or commercial funding program.
- **Resource Principles:** Development is optimized for local-first execution, minimal resource consumption, and zero required paid cloud services during early phases.
- **Future Sponsorship:** If a formal sponsorship program is established in the future, sponsorship will be managed transparently and will not override security requirements, tenant-isolation rules, or maintainer governance.

---

## 6. Review and Evolution

This governance model is designed to be lightweight and effective during the early pre-release and community-growth phases. Governance policies will be reviewed and updated as the contributor community grows.
